# AKS GPU, KVM, sandbox and stack verification, 2026-10-20

End-to-end verification of `main@2e67fae` and the three fixes in this branch on
a seven-node Azure Kubernetes Service (AKS) cluster with an NVIDIA A100 80GB
PCIe GPU, Intel VT-x KVM nodes and Istio ambient mesh. This pass starts with
the paused GPU checks from [EKS-PAUSED-2026-10-18.md](EKS-PAUSED-2026-10-18.md)
and the H6 GPU items in [LEFTOVERS.md](../LEFTOVERS.md), then exercises the
KVM/Firecracker, sandbox, Istio and post-`v0.3.0` (`#110`–`#119`) CPU checks.

No cluster credentials, endpoints or private hostnames are included. All
owned test namespaces, Helm releases, CRDs and GPU reservations were removed
at the end of the run.

## Cluster topology

- Kubernetes `v1.36.4`, Ubuntu 24.04.5 LTS, kernel `6.8.0-1070-azure` (`amd64`),
  `containerd://2.3.6-1`, Azure CNI overlay (`network-policy: none`), Istio
  ambient (`istiod`, `ztunnel`, `istio-cni-node`).
- Storage classes: `default` / `managed-csi` / `managed-csi-premium`
  (`disk.csi.azure.com`), `azurefile-csi` / `azurefile-csi-premium`
  (`file.csi.azure.com`, `ReadWriteMany`).
- Node pools:
  - 1 × `Standard_NC24ads_A100_v4` (24 vCPUs, 220 GiB RAM, 1 × **NVIDIA A100
    80GB PCIe**, Driver `580.159.04`, CUDA `13.0`, taint
    `nvidia.com/gpu=true:NoSchedule`).
  - 2 × `Standard_D8s_v5` (8 vCPUs, 32 GiB RAM, Intel Xeon Platinum 8573C with
    `vmx` and `/dev/kvm`, taint `role.node.kubernetes.io/infra=true:NoSchedule`).
  - 1 × `Standard_DS4_v2` (8 vCPUs, 28 GiB RAM, untainted).
  - 3 × `Standard_D4ds_v5` (4 vCPUs, 16 GiB RAM, Intel Xeon Platinum 8370C with
    `vmx` and `/dev/kvm`, taint `CriticalAddonsOnly=true:NoSchedule`).

## Bugs reproduced and fixed
