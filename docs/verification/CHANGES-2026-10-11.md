## 4. Retryable API writes and bulk datasets

- Persist opt-in `Idempotency-Key` claims and completed responses in SQLite or
  PostgreSQL. Recheck authentication and authorization on every retry.
- Conflict on changed input; replay completed outcomes for 24 hours; never
  automatically reexecute an unresolved claim until it is pruned (six days past
  expiry). A call that fails releases its claim; failures are not cached.
- Return generated API-key secrets only on the initial response, not from cache.
- Cover unary, bounded keyed streams, OTLP HTTP exports and raw dataset uploads.
- Cap cache storage per scope at 1024 entries and 64 MiB of response bytes.
  Serialize PostgreSQL accounting transactions with an advisory lock to prevent
  concurrent replicas exceeding these bounds; handlers execute outside it.
- Add proto-first UploadDataset and ImportDataset APIs, REST routes, generated
  Go/Python bindings, SDK methods and dataset CLI commands.
- Validate JSONL and Parquet before publishing content-addressed canonical JSONL.
  Enforce 64 MiB input/output, 100000 records, 4 MiB row/page limits and two
  active conversions per replica. Reject duplicate IDs and invalid rows without
  publishing partial datasets or echoing row contents in errors.
- Preflight Parquet page sizes/value counts; refuse external/encrypted chunks.
  Restrict S3 imports to the configured bucket's incoming project prefix.

## 5. Terminal-run deletion and quota recovery

- Add DeleteRun, REST DELETE and SDK/CLI support with explicit CLI confirmation.
- Require `runs.delete`; reject active, nonterminal or live-leased runs.
- Transactionally remove owned snapshots, records, outputs, results, leases and
  queued webhook deliveries, recovering stored-run quota.
- Keep expiring authorization-resource tombstones so deletion retries still
  evaluate current permissions after the run disappears.
- Preserve upstream datasets, promoted datasets and already-exported sink data.

## 6. Scheduled batch pulls

- Add five-field UTC cron schedules, bounded windows, starting deadlines,
  snapshot limits and durable schedule status/cursors to TraceSource.
- Coordinate pulls with source-manager leadership and a per-source two-minute
  database lease; bound a pull cycle to 90 seconds.
- Use stable window/config run IDs to reconcile a crash after run insertion.
  Wait for the previous run and lease to finish before starting another.
- Redact snapshots before batch evaluation. Do not advance the cursor on
  in-progress traces, missing fetches, repeated pagination cursors or limits.
- Count missed deadlines; advance empty windows without creating empty runs.
- Reject online policies, automatic source write-back and configured or manual
  backfill. Mirror schedule status in the operator and generated CRDs.
- Add a real Python-worker scheduled-report regression to `make e2e`.

Items 4-6 are explained in [decision 0020](../decisions/0020-pipeline-retries-and-scheduled-runs.md).

## Remaining limits

Redaction is not retrospective and does not cover upstream stores, direct
Evaluate calls or offline/run inputs. PII matching is heuristic and opt-in.
Idempotency does not cover MCP tool writes or guarantee exactly-once downstream
NATS/sink effects. Unresolved claims need reconciliation; per-scope bounds are
not a global storage or concurrent-request memory budget. Archive and automatic
run retention remain deferred. Live S3 import, production load, new-operation
HA failover, cloud connector credentials and the AKS Landlock recheck are not
certified by these local tests. The final kind run passes with Landlock deferred;
complete isolation verification still requires a supported Landlock kernel.
